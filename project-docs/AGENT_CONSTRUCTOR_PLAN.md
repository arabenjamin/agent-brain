# Agent Constructor — Design Plan

*Drafted 2026-06-12 from design discussion. Owner: Ara + brain.*

## Vision

An agent that assembles other agents. Given a Task (or subtask), the
constructor deliberately picks the four ingredients that today are chosen
statically and separately:

| Ingredient | Existing primitive | Today's selection |
|---|---|---|
| Model | `ModelSelector` (capability filter → cheapest-first, DuckDB catalog) | Background jobs pinned to `provider_hint: ollama` |
| Tools + prompt | `ContextProfile` (YAML personas: allowlist + system prompt) | Keyword `auto_assign(goal)`, one profile per chain |
| Steps | `SchedulerChain` templates / `decompose_goal` | Static keyword pattern match |
| Quality gate | Evaluator loop + adversarial pre-flight | Per-task via `success_criteria` |

An **AgentSpec** is the tuple *(model, context profile, chain steps,
success criteria)*. The constructor composes AgentSpecs per subtask,
records how they perform, and prefers what has demonstrably worked.

~70% of the pipeline already exists. The new pieces are the self-model
schema, the assembly logic, and honest usage accounting.

## Settled decisions (2026-06-12)

1. **Explicit `construct_agent` tool** callable from chat and chains;
   wired into the scheduler only after it has earned trust.
2. **Persistent AgentSpecs** — `(:AgentSpec)` nodes with performance
   history, not ephemeral plans. The history is the learning loop.
3. **Adversarial review is mandatory** for every constructed
   (non-template) chain, with a higher `min_robustness` than template
   chains get.
4. **Tiered cloud policy** (below) — enforced in code, gated on fixed
   usage accounting.

## Cloud policy (three tiers)

Context: no income at present; local 3060 Ti is the workhorse. Cloud is
for leverage, not volume, until the brain pays its own way.

- **Tier 0 — local Ollama (default).** Everything routes here unless a
  policy explicitly elevates it. This is current behavior, kept.
- **Tier 1 — Ollama Cloud free models, higher-order steps only.**
  Allowed for: `construct_agent` planning, model selection, evaluator
  scoring. Low call volume, high leverage. The existing 429→local
  fallback is the safety net. Ollama does not document which cloud
  models are free, so the brain measures it: a probe records which
  models respond vs. return payment/quota errors, written into the model
  catalog as observed availability with a timestamp.
- **Tier 2 — Gemini / Anthropic: locked.** Keys stay configured; policy
  refuses them until an explicit income-mode flag is flipped. The
  constructor may still log "would have chosen X" so the cost of the
  lock is measurable later.

The "which model is best" question is answered empirically, not from
benchmarks: evaluator scores accumulate per (model × task type) on the
actual workload via PERFORMED edges, and the constructor prefers
observed winners. The catalog only needs a periodic refresh of what is
installed/reachable; quality ranking builds itself.

## Self-model schema (Phase 0b — absorbs the "Build schema" todo) ✅ implemented 2026-06-12

Meta-graph generated by introspection at the end of every `build_skills()`
(`services/self_model.rs`) — never hand-maintained (same philosophy as
`managed_by`: files/code are truth, the graph reflects them). Full-refresh
sync: stale nodes are deleted.

- `(:ToolDef {name, description, skill, synced_at})` — from the live tool registry
- `(:ContextProfile {name, description, model_preference, provider_hint,
  allows_all, synced_at})` — from `contexts/*.yaml` via `ContextBuilderService`
- `(:ModelDef {name, provider, model, context_window, cost_per_1k_input,
  cost_per_1k_output, capabilities, synced_at})` — from the DuckDB model
  registry. (Label is `ModelDef`, not the planned `ModelSpec`, to avoid
  confusion with the Rust `ModelSpec` struct.) Observed availability /
  rate-limit annotations come later with the Tier-1 probe.
- `(:ContextProfile)-[:ALLOWS]->(:ToolDef)` — `allows_all: true` instead of
  edges when the profile's allowlist is empty
- Chains/schedules are NOT duplicated as `ChainTemplate` — `(:SchedulerChain)`
  and `(:ScheduledTask)` nodes already are the graph representation.

Phase 3 additions (not yet built):
- `(:AgentSpec {name, model, profile, steps_json, created_by})`
- `(:AgentSpec)-[:PERFORMED {score, task_type, duration_ms, cost, at}]->(:Task)`
  — written by the evaluator loop after every graded run

## Constructor flow

```
Task → decompose_goal (exists)
  → per subtask:
      1. query self-model: candidate tools (semantic match on tool
         descriptions), best profile or note the gap, candidate models
         by capability within the active cloud tier
      2. consult PERFORMED history for similar steps
      3. reuse a winning AgentSpec, or assemble a new one; emit
         ChainSteps with per-step model + context_profile + provider_hint
  → adversarial pre-flight, elevated min_robustness (exists)
  → enqueue_chain (exists) → evaluator grades (exists)
  → write PERFORMED edge → constructor gets smarter
```

Capability gaps (no decent tool/profile/model for a step) auto-create
improvement tasks — red-run takeaway #4.

## Phase 0a — usage accounting fix (trust gate, in progress)

Audit findings (2026-06-12), all confirmed in code:

1. Token counts never reach the ledger. Providers parse a combined
   `tokens_evaluated` (and Ollama drops prompt tokens entirely), but
   `SharedLlm` discards it and `model_usage.tokens_in/out` stay NULL.
   Calls are counted, tokens are not; quotas are token budgets.
2. `clients/chat.rs` (and `context_builder.rs`) build LLM clients
   directly — zero telemetry. Chat is the main cloud consumer.
3. Rate-limited cloud calls are dropped from the ledger: the 429→local
   fallback in `shared_llm.rs` returns early without recording the
   failed cloud call — the most valuable quota signal is the one
   guaranteed missing.
4. `model_usage.cost` hardcoded NULL despite registry carrying rates.
5. No time-windowed stats (quotas are hourly/daily; ledger is all-time)
   and no usage tool since the April tool reduction (REST only).

Fix scope:

- Extend `GenerateResult` with `tokens_in` / `tokens_out`; populate in
  every provider parser (Ollama `prompt_eval_count`/`eval_count`,
  Anthropic `usage`, Gemini `usageMetadata`, openai-compat `usage`).
- `SharedLlm`: pass real token counts to `record_model_usage`; record
  the failed cloud call (with an `error_kind`-style marker) before
  falling back to local.
- Instrument chat: record one `model_usage` row per chat LLM call with
  whatever usage the stream exposes (all four providers emit usage in
  their final chunk).
- `record_model_usage`: compute cost from `model_registry` rates when
  tokens are present.
- Windowed aggregation (`?hours=24`) in `get_model_stats` + restore
  brain-callable usage visibility (extend the existing tool, no new
  tool).

## Phasing

- **0a. Usage accounting** — above. Trust gate for any cloud autonomy.
- **0b. Self-model sync** — introspection meta-graph. No behavior change.
- **1. Per-step model selection** — `ChainStep.required_capabilities`,
  resolved by `ModelSelector` at dispatch within the active tier.
- **2. `construct_agent` tool** — LLM-planned AgentSpec constrained to
  the self-model; Tier 1 model for the planning call itself.
- **3. Learning loop** — PERFORMED edges, reuse-before-construct,
  capability-gap tasks, usage-aware tier escalation proposals.
